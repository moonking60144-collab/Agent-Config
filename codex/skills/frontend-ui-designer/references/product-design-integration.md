# 產品設計整合

適用於新產品方向、prototype、來源還原與視覺 audit。既有小改直接沿用產品現況，不先完成整套設計儀式。

## Brief 與視覺依據

確認畫面／使用者任務、來源、品牌與裝置限制、互動層級及成功條件。已有資訊直接使用；不要重新詢問或把 brief 整理當成成果。

Screenshot、Figma、實際 render 或已開啟的 URL 都可作來源；單張截圖只能證明可見狀態，不代表其他尺寸、hover 或完整流程。來源缺少的細節依既有系統推斷並標示，不因沒有第二張圖就禁止實作。

新方向尚未決定且選擇會實質影響成果時，可提供少量具體候選；使用者已選方向或授權自行設計時直接完成，不強制先讓使用者挑 2 到 3 個 mock。

## 來源還原

- 從可取得的來源辨識版面、typography、tokens、素材及主要互動。只擴查對本次 fidelity 有影響的缺口。
- 保留來源的語意層級、內容關係、主要 controls 與品牌識別；不能只仿色彩而換成通用模板。
- 區分真正素材、授權替代及明確未取得的項目；記錄會影響還原度的替換，不用占位圖冒稱完成。
- 未提供的 responsive／互動狀態可以依產品模式實作，但不得宣稱與來源逐項一致。
- 不因探索更多頁面而擴大本次交付 routes、功能或外部寫入。

## 原型與正式介面

除非指定靜態，主要 navigation、CTA、tab、filter、modal、form 等應可操作。資料畫面使用合理 fixture，並處理與任務相關的 loading、empty、error／validation。模擬 API 或假資料須明確標示，原型互動不代表後端已接通。

正式 UI 仍須沿 caller → contract → consumers 驗證實際行為；來源截圖與展示原型不能代替這項證據。

## QA 與 Audit

Design QA 檢查已實作結果是否符合來源；Audit 檢查產品流程的問題，未獲實作授權時維持唯讀。

以相同 viewport、theme、state 與內容比較：文字換行、層級、對比、alignment、素材裁切、捲動與主要操作。裝置差異依 [responsive checklist](responsive-checklist.md)，一般設計與文案依 [skill](../SKILL.md)，不重複填表。

Findings 綁定具體畫面／步驟／狀態。主要流程不可用、必要資訊不可讀或來源核心關係未還原時，不宣稱設計完成；不可測項目列限制。

## 交付

依主 skill 的交付原則，提供 URL／檔案、完成範圍、重要替換或設計取捨與實際 QA 結果；缺口只交代影響使用或驗收者及其具體影響。設計策略、handoff 與驗收註解留在交付說明。
